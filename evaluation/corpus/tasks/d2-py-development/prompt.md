# Finch: an order create with no returned resource ID

The command `{intentId,accountId,deliveryId}` requests an approval-ready order for the immutable authorized `intents[intentId]` quote (accountId, authorized, amountMinor, currency). This service creates orders only. There is no search-by-request-ID API. A network/read failure, malformed response or optional-field-only success may occur after the provider creates an order. Keep that attempt unknown and durably prevent another create, even when the next worker receives a different deliveryId.

A confirmed valid ID and matching purchase quote returns ready/200 with orderId and persists `order_requests[intentId]` with state:'ready', orderId and the frozen request identity. A replay of a confirmed request returns the original orderId without creating another order. An uncertain request returns unknown/202. OAuth failure before dispatch returns not_sent/503 and permits a later caller retry with the same business identity. An explicit 4xx payment refusal returns refused/422. Missing intent returns missing/404; foreign account or revoked authority returns forbidden/403. Unknown optional fields must not be stringified into fake IDs. Distinct intents must remain distinct even when delivery IDs collide. Unexpected store or programming exceptions must propagate.
