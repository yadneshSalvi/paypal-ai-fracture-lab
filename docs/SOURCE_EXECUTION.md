# Private imported checkout execution

An authenticated private developer owner can prepare and separately approve one immutable imported TypeScript checkout. Public judge sessions keep their curated runner. A Source Atlas browser-view approval remains read-only, and the original static import, source bytes, graph, flags and receipts are never rewritten.

The adapter requires `export async function checkout(context: BrambleContext): Promise<unknown>`. Import that interface with `import type { BrambleContext } from "@fracture/source-target"`. Literal relative TypeScript imports form a sealed closure of at most 64 files and 2 MiB. The pinned public `@fracture/paypal-core` and `node:crypto` are supported runtime dependencies; `@fracture/contracts` and the virtual adapter are type-only. Package scripts, installation, Python/browser targets, absolute/dynamic modules, unlisted dependencies, collisions, traversal, invalid hashes and reflective/process capabilities are refused with a retained reason. Static checks are admission checks; the independent runtime is the isolation boundary.

## Service and persistence

`packages/source-execution/src/index.ts` exports strict input schemas, DTOs, `SourceExecutionService`, the executor protocol and additive `sourceExecutionSchema`/`initializeSourceExecution(db)`. Supply an existing `LabStore`, its `SourceAccessStore` and a trusted qualified runner identity. Authenticate the developer credential through existing `DeveloperAccess` before constructing `{sessionId, grantId}`; identifiers alone are not authentication.

- `prepare(owner, {importId, entryPath, expectedRevisionHash, scenarioIds, seed, requestId})` reads accepted source only through `SourceAccessStore.report`, and saves the exact files, edges, snapshot/manifest/revision, original authority, adapter, complete public-suite manifest, selection, seed and runner hashes. It returns `{command, plan}` and its limitations before execution.
- `approve(owner, {planId, expectedPlanHash, requestId})` durably creates one job and its original case identities, returning `{command, job}`. Repeating an identical UUID/body returns the original acceptance; a changed body conflicts. A second approval identity cannot execute the same plan again.
- `getCommand(owner, requestId)`, `getPlan(owner, {planId})`, `getJob(owner, {jobId})`, `list(owner, {limit})` and `report(owner, {jobId})` support GET-first ambiguous-response recovery. Reports contain private source, trace, compiler, assertions, runner/disposal identity and digests; never publish them as public artifacts.
- `cancel(owner, {jobId, requestId})` stops pending cases and aborts owned execution, preserving completed failures and uncertain observations. Confirmed disposal and unknown cleanup produce different states. It never compensates payments or deletes source.
- `claimNext(workerId)`, `executeClaim(claim, executor)` and `runNext(workerId, executor)` use compare-and-set ownership. Dispatched or interrupted work is never automatically redispatched. Its original external execution name stays retained, including loss of an acknowledgment.

All source reads and mutations recheck the exact original import owner grant, role, full session/grant/import expiries and the grant-token fingerprint. Execution also has a fixed bounded approval window. No extension or replacement renews the old plan. Completed records remain readable only while their original authority is current. A worker checks again before every case, during execution, and before publication; an ended authority withholds late success and admits no later case.

The only added tables are `lab_source_execution_plans_v1`, `lab_source_execution_commands_v1`, `lab_source_execution_jobs_v1`, `lab_source_execution_cases_v1`, `lab_source_execution_events_v1` and `lab_source_execution_artifacts_v1`. Execute the exported SQL statements in order on the explicitly configured database. Existing `lab_sessions`, `lab_developer_grants`, `lab_source_imports`/`lab_source_files` and accepted SourceAccessStore documents are read contracts. No existing schema, row, import, source-view grant or study is migrated by this package.

## Current runner and exact boundaries

The current implementation is a **new Docker lane**. Preparation uses the immutable already-qualified local dependency image and public dependency inputs; it does not install packages, pull images or call Docker. `scripts/prepare-source-isolation.ts --public-context <absolute qualified context>` writes a new content-addressed context, complete file manifest, recipe and input hashes under ignored `.artifacts/source-execution-stage10/contexts/`. An existing context is refused. Build/run require the separately coordinated exact qualification; the original image, tag, source contexts and runtimes remain unchanged.

`DockerSourceExecutor` explicitly selects `colima-fracture-lab`, the approved immutable new image ID, denied networking, zero host mounts, read-only root/reference, 512 MiB memory, one CPU, 96 processes, bounded noexec temporary storage and a fixed deadline/output limit. A trusted root-owned supervisor retains only SETUID/SETGID to spawn the unprivileged UID1000 compiler/target and a same-UID termination helper. The imported child verifies UID/GID1000, no effective/permitted capabilities and no-new-privileges. It never receives host environment, database, model, browser or payment credentials. The immutable reference and staged imported modules are root-owned and checked before/after execution.

The target executes in a separate process through typed capability RPC. A private per-case Sample SQLite database and trusted assertions stay in the supervisor. Target application events cannot forge provider observations or alter tests/reference. Child stdout/stderr is a separate bounded channel; it cannot be parsed as the supervisor receipt. Unknown/malformed output, timeout, output limit, compiler rejection, failed target assertions and unknown cleanup remain separate. The adapter requires verified stopped/removal evidence before admitting a passing result.

The exact original nine-case suite file is preserved with SHA256 `c3e3c478c3af78f82ba966e946cb578ef31b8a039855d920a65402adad190239`. Its case definitions and eight assertion predicates are unchanged. Case names are `happy`, `lost`, `malformed`, `unavailable`, `pending`, `auth`, `concurrent`, `revoked`, `payload`. The selected seed is bound to the per-case input alongside all source/config identities. These are public **Sample/local-fixture** checks, with no financial-provider or hidden-suite claim. Imported entry/relative helper bytes are actually used; the curated checkout is never substituted.

The protocol also defines a separate strict `vercel-sandbox` identity/receipt arm for the integration owner's future hosted adapter: exact snapshot, deny-all networking, writable VM root, immutable root-owned reference, unprivileged candidate, explicit bounded VM/vCPU/deadline/output and stopped cleanup. This unit implements and qualifies Docker only. One lane cannot satisfy the other lane's identity or isolation proof.

## Local worker and verification

`scripts/source-execution-worker.ts` runs at most one saved job and creates no listener. It requires an explicit private runner identity and either an existing private fixture SQLite file or the separately assigned `FRACTURE_SOURCE_EXECUTION_DATABASE_URL`, `FRACTURE_SOURCE_EXECUTION_EXPECTED_DATABASE`, `FRACTURE_SOURCE_EXECUTION_EXPECTED_ROLE` and `FRACTURE_SOURCE_EXECUTION_EXPECTED_PORT`. It never loads `.env`, uses application `DATABASE_URL`, silently migrates the base schema or creates actors. The standalone qualification worker refuses unassigned local identities.

Focused tests use fresh temporary persistence and clearly labeled receipt doubles for state/authority/concurrency faults. Those tests are not an actual sandbox receipt. Real multi-file faulty/control, protocol-forgery, capability-mutation, limits and cancellation qualification are separately recorded against the new immutable image. Preserve first failures and rerun only after a relevant change. No old study, candidate, source import, fixture actor or expiry is reset or reused by this capability.

## Recorded local qualification

The bounded Docker qualification executed two distinct, genuinely multi-file imports under the unchanged nine public checks: the declared faulty revision passed two and failed seven; the corrected revision passed all nine. The runner retained source markers proving the selected entry and relative helper ran. All 26 declared runtimes returned receipts and confirmed removal. Separate cases rejected forged stdout, bounded output and compilation errors, recorded a real timeout, preserved the first failed case through cancellation, and withheld later admission after grant revocation.

The original qualification retains seven passing groups and one failed filesystem-errno expectation: all thirteen capability attempts were denied, but the pinned core's recursive mkdir returned `ENOENT`. That assertion was not changed or rerun. A separately declared trusted OS diagnostic in the same immutable image measured UID/GID1000, no effective/permitted capabilities and no-new-privileges, received native `EROFS` from a direct reference write, preserved all 169 reference-file hashes, and confirmed disposal. It executed no imported code or compiler. SQL qualification used a separately assigned least-privilege local PostgreSQL database; no original application database, actor, source import or study was changed.

These observations qualify this bounded **Sample Docker backend**. The strict hosted Sandbox arm, product API/MCP/CLI registration, browser controls and ordinary remotely initiated journey belong to the integration owner and require their own receipts. Private qualification sources and reports are not public artifacts.
