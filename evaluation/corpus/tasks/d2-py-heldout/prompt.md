# Cedar: reconcile a partial refund from an authenticated later reference

The command `{refundIntentId,accountId,observedRefundId?}` operates on an immutable `refund_intents[refundIntentId]` authorization containing accountId, intentId, captureId, amountMinor and currency. The command's observedRefundId is an untrusted hint from a later delivery; it is not permission to apply a different refund. The first invocation may issue the authorized partial refund once. Persist its claim before dispatch using a stable provider identity. A missing or invalid answer may hide a committed refund; preserve that uncertainty and do not resend on later calls.

If a returned refund ID or later hint exists, use the supported refund GET and match custom identity (`custom_id` equals refundIntentId), amount and currency before recording it. An unrelated refund, even on the same capture for the same amount, cannot complete this intent. A valid matching COMPLETED refund marks `refund_intents` completed and returns completed/200 with refundId. A matching PENDING result stays pending/202. No valid reference means unknown/202; a wrong hint returns conflict/409 without moving money or discarding the original protection. Forbidden account returns forbidden/403 without provider traffic. Authentication before dispatch is not_sent/503; known provider refusal is refused/422. Do not release or fabricate a successful unknown result; keep programming/store failures visible.
