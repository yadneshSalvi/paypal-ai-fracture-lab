# Mosaic: local refund reservations coexist with external refunds

Handle `{refundIntentId,accountId,attemptId}`. `refund_authorizations[refundIntentId]` is immutable approved authority with accountId, intentId, captureId, amountMinor and currency. The intents row stores the original captured amount. `refund_external[captureId]` is a trusted reconciliation snapshot with externalRefundedMinor; it includes refunds made outside this application and excludes all refunds represented in the local reservations table. Its value may advance between calls. Do not count the same local refund twice by subtracting both it and the provider's partial-refund status.

Before dispatch, verify the bound capture's custom identity, currency and original amount. Atomically reserve capacity against original amount minus externalRefundedMinor. Held, unknown, pending and completed local reservations all consume this remaining capacity. A competing refund that cannot fit must return capacity/409 locally before sending another refund request. Duplicate semantic refund intents share one persisted provider identity and body regardless of attemptId. Preserve capacity when an answer is lost or pending; a proven pre-dispatch failure or explicit refusal can release it.

After a matching COMPLETED refund, insert one `refund_results[refundIntentId]` with refundId, captureId and amountMinor. Return completed/200 with refundId, pending/202, unknown/202, capacity/409, forbidden/403, refused/422 or not_sent/503. Reconcile a known refund ID on replay; do not resend an unknown result without an ID. Unexpected programming/store failures must escape. All quoted and reconciled values are integer minor units.
