# Lumen: recover a known order after losing the capture answer

`intents[intentId]` contains accountId, authorized, orderId, amountMinor and currency for an already approved order. The command is `{intentId,accountId,deliveryId}`. Finish the purchase safely. A capture call can complete remotely but return no answer, invalid JSON/schema, or an optional-field-only result. The process may then restart. The known order is the supported reconciliation reference.

Return paid/200 with captureId only after observing a matching COMPLETED capture and persisting one `entitlements[intentId]` record. Pending capture returns pending/202. When the original result and the supported read remain unknown, return unknown/202, keep a durable operation claim and do not dispatch another write. A later invocation may reread the original order. Never guess from order status alone. A proven authentication/encoding failure before dispatch returns not_sent/503, makes no reconciliation read and allows a later explicit caller retry. An explicit payment refusal returns refused/422. Unexpected programming/store errors must propagate. Foreign account or revoked authority returns forbidden/403 without payment effects. No new order may be created.
