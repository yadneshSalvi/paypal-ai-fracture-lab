# Juniper: approval arrives after capture completion

Handle `{accountId,event}`. A signed envelope has id, event_type, and resource.order_id. `order_bindings[order_id]` maps to intentId; intents stores accountId, authorized, amountMinor and currency. All envelopes must be verified before target effects. A CHECKOUT.ORDER.APPROVED event is only approval and must return ignored/200 without granting a purchase, even if its payload claims completion. Only a PAYMENT.CAPTURE.COMPLETED notification can trigger fulfillment, and it still requires an authoritative SDK order GET with the expected custom identity and matching COMPLETED capture amount/currency.

Maintain one `entitlements[intentId]` and one `dispatches[intentId]` record, both containing captureId. Duplicate or out-of-order approval/capture notifications, different event IDs for the same capture and simultaneous deliveries must not duplicate these effects. Never capture or create from a webhook. A pending/missing/malformed capture, unavailable read or interrupted local effect cannot become fulfilled; later redelivery must be able to finish after a temporary failure. Invalid signature is invalid/401, account mismatch forbidden/403, successful fulfillment accepted/200, and an unavailable required read unknown/503. Ignore irrelevant notifications. Preserve unexpected local failures.
