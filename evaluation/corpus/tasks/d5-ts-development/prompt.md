# Errand: a new tool call is still the same approved job

Handle `{jobId,accountId,toolCallId,arguments:{intentId,amountMinor,currency}}` for the create_order tool. `agent_jobs[jobId]` contains accountId, approved, intentId and budgetMinor; the immutable intents row contains accountId, authorized, amountMinor and currency. Match all arguments to the authorized intent and budget before provider traffic. Reject altered arguments, revoked authority or foreign scope with denied/403, code POLICY_DENIED, retryable:false. A job's semantic create identity must survive new toolCallIds, model replanning and worker restarts.

Persist the operation before dispatch and use the SDK provider request-ID field. A confirmed matching order returns ready/200, code ORDER_READY, retryable:false and orderId. Save it in `tool_results[jobId]`. A duplicate confirmed job returns that original resource. Unknown creation with no valid order ID returns unknown/202, code OUTCOME_UNKNOWN, retryable:false, remains protected and must not invent a lookup or create again. Optional fields are not an ID. Authentication or encoding before dispatch is not_sent/503, code AUTHENTICATION_UNAVAILABLE or INVALID_REQUEST, retryable:true and can be retried after a caller fixes the cause. A provider 4xx refusal returns refused/422, retryable:false and a typed issue code when available, otherwise PROVIDER_REFUSAL. Unknown/default error arms must degrade safely. Keep unexpected programming/store errors visible.
