# Copper: a refund answer is not a capture balance

This read-only reconciliation worker receives `{refundIntentId,accountId}` after another service dispatched a refund and lost its answer. `refund_intents[refundIntentId]` contains accountId, intentId, captureId, amountMinor, currency, state:'unknown' and optionally refundId. If present, refundId is an authenticated persisted provider reference from the original operation. The row may be updated with that reference by the separate authorized ingestion service before a later invocation.

Repair reconciliation without issuing a write. Read the known refund with the SDK, validate its ID, custom identity (`custom_id` equals refundIntentId), amount and currency. COMPLETED marks the local row completed and returns completed/200 with refundId. PENDING must remain pending/202 and preserve the amount. Other statuses, missing fields, malformed responses, inaccessible reads and absence of a known refund ID return unknown/202. A partial/full capture balance cannot identify which refund intent succeeded; an unrelated refund must never settle this one. A foreign account returns forbidden/403 with no provider traffic. No speculative refund, search by request ID, or release of uncertainty is permitted. Programming/store errors must remain visible.
