# Postmark: a retryable webhook and one delivery message

Handle `{accountId,event}` with envelope id, event_type and resource.id. Verify the exact envelope first. For PAYMENT.CAPTURE.COMPLETED, use `capture_bindings[resource.id].intentId` and the corresponding authorized intents row (accountId, amountMinor, currency). The event payload is a notification, not authoritative payment state. Read the bound capture with the SDK and require matching ID, custom identity, COMPLETED status, exact amount and currency.

Grant one `entitlements[intentId]` row with captureId and amountMinor, and enqueue one `notification_outbox[intentId]` record with captureId and kind:'purchase_receipt'. The outbox is a durable local effect, not an actual email send. Duplicate event IDs, distinct notifications for the same payment, concurrent delivery and a worker/store failure between effects must not duplicate or lose either effect. A failed read or store write must allow a later delivery to finish. After successful processing, the same event ID with a different authenticated envelope returns conflict/409. Identical successful repeats return accepted/200. Invalid signature invalid/401, foreign account forbidden/403, irrelevant event ignored/200, and unavailable required read unknown/503. No payment write or external message send is allowed. Unexpected exceptions must escape.
